# 开发日志 — 单 Skill 对话页与运行审计

**目标**：在现有 Skill Store / Agent 导入链路基础上，新增一个“单开 Skill 的对话页面”。主对话里的 `@agent` 调用逻辑不重写；本次新增页面只允许调用当前详情页对应的已批准 Skill。

**本期范围**：仅支持已导入、已安装、已批准启用、无 MCP 依赖的本地 Skill；不新增数据库表；运行日志复用 `event_logs`；导入/权限/环境结果继续复用 `skill_imports` 最新记录。

---

## [S1] 后端 · 单 Skill Chat 服务

- 新增文件：`server/utils/agents/skillChat/index.js`
- 新增接口：`POST /api/skills/store/:slug/stream-chat`
- 路由文件：`server/endpoints/skillStore.js`

### 调用前置检查

`SkillChat.preflight` 会按顺序检查：

- 读取 `SkillStore.getWithImport(slug)`，拿到详情页同源数据：描述、SKILL.md 能力范围、完整性、最新导入记录。
- 检查 `skill_imports` 最新记录存在且 `status === "success"`。
- 读取已安装插件目录 `server/storage/plugins/agent-skills/<slug>/plugin.json`。
- 检查插件 `active === true` 且详情页安装状态为 `installed-active`。
- 检查 `permissionRequest.decision === "approved"`。
- 检查 `envResult.compatible === true`。
- 检查 `completeness.runnable !== false`。
- 检查 `handler.js` 已安装且可被 `ImportedPlugin.validateImportedPluginHandler(slug)` 找到。
- 选择运行工作空间：优先请求参数，其次导入报告中的 `conversationRef.workspaceSlug`，最后取第一个 workspace。

### 单 Skill 限制

- 运行时调用现有 `EphemeralAgentHandler`，没有重造 Agent。
- 通过 `toolOverrides: ["@@<slug>"]` 限制本次 Agent 只加载当前 Skill。
- 注入 Prompt 中包含：
  - Skill 标题 / slug / 描述
  - SKILL.md 能力范围摘要
  - `plugin.json.entrypoint.params` 输入格式
  - 输出格式约定
  - 调用方式
  - examples
  - 已批准权限摘要

### 运行日志

运行日志写入现有 `event_logs`：

- `skill_chat_invocation`：用户请求摘要、Skill 匹配结果、Prompt 注入情况、受限工具列表。
- `skill_chat_completed`：响应摘要、工具调用摘要、metrics、最终状态。
- `skill_chat_error`：预检失败或运行异常、失败原因、已知匹配状态。

日志中不写完整 Prompt，不写敏感环境变量，只保留摘要和状态字段。

## [S2] 后端 · Imported Skill 运行入口兼容

- 修改文件：`server/utils/agents/imported.js`

### 背景

前面标准模板与一键补全器约定的是：

```js
module.exports.runtime = {
  execute: async function (args) {
    return { success: true, output: "..." };
  },
};
```

但 AnythingLLM Agent 运行时实际调用的是 `handler(args)`。因此本次增加兼容层：

- 优先使用 `runtime.handler`。
- 没有 `handler` 时自动使用 `runtime.execute`。
- 若返回 `{ output }`，自动转成字符串传给 Agent。
- 保留 `this` 上下文，避免已有 handler 依赖 `this.super` 时失效。

这不是新的桩函数，是为了让标准 Skill zip 模板、补全生成结果、主对话 `@agent` 和单 Skill 对话页使用同一个运行契约。

## [S3] 前端 · 单 Skill 对话页面

- 新增页面：`frontend/src/pages/GeneralSettings/CommunityHub/SkillChat/index.jsx`
- 新增路由：`/settings/community-hub/skills/:slug/chat`
- 新增路径 helper：`paths.communityHub.skillChat(slug)`
- 修改模型层：`frontend/src/models/skillStore.js` 新增 `streamChat`
- 修改详情页：`SkillDetail` 中“去对话”改为“单独对话”，跳转到当前 Skill 的 chat 页面。

### 页面行为

- 左侧：独立对话区，展示用户消息、Agent Thought、Skill 返回结果和错误。
- 右侧：调用前检查面板，展示详情/导入记录、权限、环境、文件可运行、已启用状态。
- 未通过预检时，输入框禁用并显示阻断原因。
- 请求走 SSE，复用后端已有 chunk 类型：`agentThought`、`textResponseChunk`、`textResponse`、`finalizeResponseStream`、`abort`。
- 页面输出用 `DOMPurify.sanitize(renderMarkdown(...))` 清洗，避免 Skill 输出 HTML 时直接注入。

## [S4] 与商店导入链路的关系

- Skill Store 拖入 zip 的导入流程未重写，继续走：
